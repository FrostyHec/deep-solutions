## Core Directories

### `src/deep_solutions/` - Source Code

Uses **src-layout**, the recommended structure for Python packages:

- **Advantage**: Forces importing from installed package, avoiding issues with direct source directory imports
- **`__init__.py`**: Defines public API, all externally exposed classes/functions are exported here
- **`_version.py`**: Auto-generated by `setuptools-scm`, contains version information

```python
# Adding new module exports (src/deep_solutions/__init__.py)
from .your_module import YourClass, your_function

__all__ = [
    "YourClass",
    "your_function",
    # ... other exports
]
```

### `tests/` - Test Directory

- Test files start with `test_`
- Test functions start with `test_`
- Uses pytest framework

### `scripts/` - Scripts Directory

| Script | Purpose |
|--------|---------|
| `check.sh` | One-click development check (format + lint + type check + test) |
| `ci-local.sh` | Simulate full CI workflow (suitable for pre-PR verification) |
| `check_language.py` | Check language requirements (English-only source code, bilingual docs) |

### `.github/workflows/` - CI/CD Workflows

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| `ci.yml` | PR / Push to main | Code quality checks and testing |
| `report.yml` | After CI completion | Publish test reports to PR |
| `publish.yml` | Manual trigger | Publish to PyPI |
| `publish-test.yml` | Manual trigger | Publish to TestPyPI |

## Dependency Management

### Dependency Categories

Project dependencies are defined in `pyproject.toml`:

#### Core Dependencies (dependencies)

Runtime required dependencies:

```toml
dependencies = [
    "numpy>=1.17.0",
    "scipy>=1.5.0",
]
```

#### Development Dependencies (optional-dependencies.dev)

Tools needed for development:

```toml
[project.optional-dependencies]
dev = [
    "pytest>=7.0.0",        # Testing framework
    "pytest-cov>=4.0.0",    # Test coverage
    "ruff>=0.4.0",          # Code formatting & lint
    "mypy>=1.0.0",          # Type checking
    "build>=0.10.0",        # Package building
    "twine>=4.0.0",         # Package publishing
    "tox>=4.0.0",           # Multi-version testing
    "tox-gh>=1.0.0",        # GitHub Actions integration
    "commitizen>=3.0.0",    # Commit message tool
    "pre-commit>=3.0.0",    # Git hooks
]
```

#### Documentation Dependencies (optional-dependencies.docs)

Dependencies for building documentation:

```toml
docs = [
    "sphinx>=6.0.0",
    "sphinx-rtd-theme>=1.2.0",
]
```

### Installation Methods

```bash
# Install core dependencies only
pip install .

# Install core + dev dependencies (recommended for development)
pip install -e ".[dev]"

# Install all dependencies
pip install -e ".[dev,docs]"
```

### Adding New Dependencies

1. Edit the appropriate dependency list in `pyproject.toml`
2. Reinstall: `pip install -e ".[dev]"`

> **Note**: Do not add Python packages in `environment.yml`, it's only for managing Python version.

## Python Version Requirements

### Supported Versions

| Python Version | Status |
|----------------|--------|
| 3.8 | ✅ Supported (development version) |
| 3.9 | ✅ Supported |
| 3.10 | ✅ Supported |
| 3.11 | ✅ Supported |
| 3.12 | ✅ Supported |
| 3.13 | ✅ Supported |

### ⚠️ Development Must Use Python 3.8

**Reasons**:

1. **Compatibility guarantee**: Python 3.8 is the minimum supported version; only code that runs correctly on 3.8 can guarantee forward compatibility
2. **Syntax restrictions**: Avoid using syntax only available in higher versions (like `match-case`, `|` type union)
3. **Type annotations**: Use `typing` module for backwards compatibility, not built-in type annotations

**Incompatible Examples**:

```python
# ❌ Python 3.10+ syntax - DO NOT use
def process(data: list[int] | None) -> dict[str, int]:
    match data:
        case None:
            return {}

# ✅ Python 3.8+ syntax - Use this approach
from typing import Optional, List, Dict

def process(data: Optional[List[int]]) -> Dict[str, int]:
    if data is None:
        return {}
```

### Configure Development Environment

```bash
# Create Python 3.8 environment
conda create -n deep-solutions python=3.8 -y
conda activate deep-solutions

# Install dependencies
pip install -e ".[dev]"
```

## Configuration Files

### `pyproject.toml`

Core project configuration file containing:

| Section | Description |
|---------|-------------|
| `[build-system]` | Build system configuration (setuptools) |
| `[project]` | Package metadata (name, version, description, dependencies, etc.) |
| `[tool.setuptools_scm]` | Automatic version management configuration |
| `[tool.ruff]` | Ruff formatting and lint configuration |
| `[tool.pytest.ini_options]` | pytest configuration |
| `[tool.mypy]` | mypy type checking configuration |
| `[tool.commitizen]` | Commitizen configuration |

### `tox.ini`

Multi-version testing configuration:

```ini
[tox]
envlist = py38,py39,py310,py311,py312
```

### `.pre-commit-config.yaml`

Pre-commit hooks for code quality and commit message validation.

### `environment.yml`

Conda environment configuration (Python version only):

```yaml
name: deep-solutions
dependencies:
  - python=3.8
```

## Version Number Management

The project uses **setuptools-scm** for automatic version management:

- **Version source**: Git Tag (e.g., `v1.0.0`)
- **Auto-generated**: `src/deep_solutions/_version.py`
- **Runtime reading**: Via `importlib.metadata`

```python
# Get version in code
import deep_solutions
print(deep_solutions.__version__)
```

### Version Number Convention

Follows [Semantic Versioning](https://semver.org/):

```
vMAJOR.MINOR.PATCH

- MAJOR: Incompatible API changes
- MINOR: Backwards-compatible feature additions
- PATCH: Backwards-compatible bug fixes

Examples:
- v1.0.0     - Stable release
- v1.0.0rc1  - Release Candidate
- v1.0.0a1   - Alpha
- v1.0.0b1   - Beta
```
