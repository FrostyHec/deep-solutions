# PyPI 发版指南

## 📋 概述

本指南介绍如何发布 `deep-solutions` 包到 PyPI 和 TestPyPI。项目使用 GitHub Actions 工作流，通过手动触发进行发布。

## 🔑 前置条件

### 1. 生成 PyPI API Token

#### 生成 PyPI 正式环境的 Token

1. 访问 [PyPI 账户设置 - API Tokens](https://pypi.org/manage/account/tokens/)
2. 点击 "Add API token"
3. 选择作用域：
   - 如果只想发布本项目：选择 "Scope: deep-solutions"
   - 如果想发布所有项目：选择 "Scope: Entire account (not recommended)"
4. 复制生成的 token（格式如 `pypi-AgEIcHE...`）

#### 生成 TestPyPI 的 Token

1. 访问 [TestPyPI 账户设置 - API Tokens](https://test.pypi.org/manage/account/tokens/)
2. 重复上述步骤

### 2. 在 GitHub 仓库中配置 Secrets

#### 步骤

1. 进入仓库 → Settings → Secrets and variables → Actions
2. 点击 "New repository secret"

#### 需要添加的 Secrets

| Secret 名称 | 值 | 说明 |
|-----------|-----|------|
| `PYPI_API_TOKEN` | PyPI API Token | 用于发布到 PyPI 正式环境 |
| `TEST_PYPI_API_TOKEN` | TestPyPI API Token | 用于发布到 TestPyPI 测试环境 |

**⚠️ 安全提示：**
- 不要将 Token 提交到代码仓库
- 不要在任何文档中公开 Token
- Token 一旦泄露应立即重新生成

### 3. 配置 GitHub Actions 环境

在仓库的 GitHub Actions 环境中配置 Secrets。这已在以下工作流中配置：
- `.github/workflows/publish.yml` (uses `environment: pypi`)
- `.github/workflows/publish-test.yml` (uses `environment: testpypi`)

## 🚀 发布流程

### 快速查询

| 场景 | 工作流 | 触发方式 | 目标 |

| 测试发布 | Publish to TestPyPI | 手动触发 | TestPyPI |

## 📤 发布到 TestPyPI（测试环境）

### 何时使用？

- 在正式发布前进行完整测试
- 验证包的构建和安装过程
- 测试新的版本格式（如 `v1.0.0rc1`, `v2.0.0.dev1` 等）

### 操作步骤

#### 步骤 1: 准备代码

确保所有代码已提交并且在正确的分支上：

```bash
# 确保当前在 main 分支
git checkout main

# 拉取最新代码
git pull origin main

# 验证代码状态
git status
```

#### 步骤 2: 触发工作流

1. 进入 GitHub 仓库
2. 点击 **Actions** 标签
3. 在左侧列表中选择 **"Publish to TestPyPI"**
4. 点击 **"Run workflow"** 按钮
5. 输入版本标签（如 `v1.0.0-test`, `v1.0.0rc1` 等）
6. 点击 **"Run workflow"** 按钮确认

#### 步骤 3: 监控发布过程

1. 工作流会自动运行
2. 查看 Actions 页面，确保所有步骤都通过
3. 如果任何步骤失败，查看日志了解原因

#### 步骤 4: 验证发布结果

在 [TestPyPI](https://test.pypi.org/) 上查看包是否成功上传：

```bash
# 在本地环境测试安装
python -m venv test-env
source test-env/bin/activate

pip install --index-url https://test.pypi.org/simple/ \
            --extra-index-url https://pypi.org/simple/ \
            deep-solutions

# 验证安装
python -c "import deep_solutions; print(deep_solutions.__version__)"
python -c "from deep_solutions import hello_world; print(hello_world())"

deactivate
```

## 🎉 发布到 PyPI（正式环境）

### 何时使用？

- 准备好正式发布新版本
- 所有测试都通过
- 文档已更新

### 版本号格式

遵循 [Semantic Versioning](https://semver.org/) 和 [PEP 440](https://peps.python.org/pep-0440/)：

| 版本号 | 说明 | 例子 |
|------|------|------|
| Major.Minor.Patch | 正式发布 | `v1.0.0`, `v2.1.3` |
| Major.Minor.PatchrcN | Release Candidate | `v1.0.0rc1`, `v1.0.0rc2` |
| Major.Minor.PatchaN | Alpha | `v1.0.0a1` |
| Major.Minor.PatchbN | Beta | `v1.0.0b1` |
| Major.Minor.Patch.postN | Post-release | `v1.0.0.post1` |

### 操作步骤

#### 步骤 1: 更新文档和版本

在 main 分支上进行最后的准备：

```bash
# 更新 CHANGELOG.md
# 记录新版本的更改（可选，取决于你的工作流）

# 提交这些更改
git add CHANGELOG.md
git commit -m "chore: prepare release v1.0.0"
git push origin main
```

#### 步骤 2: 触发发布工作流

1. 进入 GitHub 仓库
2. 点击 **Actions** 标签
3. 在左侧列表中选择 **"Publish to PyPI"**
4. 点击 **"Run workflow"** 按钮
5. 输入版本标签（如 `v1.0.0`, `v2.1.0`, 等）
6. 点击 **"Run workflow"** 按钮确认

#### 步骤 3: 工作流会自动执行以下操作

1. 创建 Git Tag（如果不存在）
2. 在所有 Python 版本 (3.8-3.12) 上运行测试
3. 构建包（sdist + wheel）
4. 验证包的完整性
5. 上传到 PyPI
6. 等待 60 秒以确保包可用
7. 验证从 PyPI 的安装
8. 创建 GitHub Release

#### 步骤 4: 验证发布

在 [PyPI](https://pypi.org/) 上查看包：

```bash
# 在新的环境中测试安装
python -m venv verify-env
source verify-env/bin/activate

pip install deep-solutions

# 验证版本和功能
python -c "import deep_solutions; print(deep_solutions.__version__)"
python -c "from deep_solutions import hello_world; print(hello_world())"

deactivate
```

#### 步骤 5: 通知用户

发布后，你可以：
- 在 GitHub Release 中添加发行说明
- 在项目文档中更新版本号
- 在社交媒体或社区中发布通知

## 🔄 发布不同版本类型

### 发布 Release Candidate (RC)

用于发布候选版本进行社区测试：

```
工作流：Publish to TestPyPI (首选) 或 Publish to PyPI
版本标签：v1.0.0rc1, v1.0.0rc2 等
目标：允许用户测试新功能
```

### 发布 Alpha/Beta 版本

用于早期预发布：

```
工作流：Publish to TestPyPI
版本标签：v1.0.0a1, v1.0.0b1 等
目标：内部测试或早期用户反馈
```

### 发布开发版本

用于持续集成环节的中间测试：

```
工作流：Publish to TestPyPI
版本标签：v1.0.0.dev1, v1.0.0.dev2 等
目标：开发者验证
```

### 发布后修复版本

用于已发布版本的热修复：

```
工作流：Publish to PyPI
版本标签：v1.0.0.post1, v1.0.1 等
目标：紧急问题修复
```

## 📝 分支发布策略

### 推荐流程

```
main 分支（生产就绪）
    ↓
    [准备发布，更新文档]
    ↓
    [手动触发 Publish to PyPI 工作流]
    ↓
    [选择版本标签 v X.Y.Z]
    ↓
PyPI 发布完成 ✓
```

### 不同分支的建议

| 分支 | 用途 | 发布策略 |
|------|------|--------|
| `main` | 生产代码 | 正式发版（Publish to PyPI）|
| `develop` | 开发代码 | 测试发版（Publish to TestPyPI）|
| `feature/*` | 功能分支 | 不发版 |
| `hotfix/*` | 紧急修复 | 临时发版（v X.Y.Z.post1）|

## ⚠️ 常见问题与排查

### Q1: 发布失败，显示 "API Token 无效"

**原因**：Token 可能已过期或配置不正确

**解决**：
1. 检查 GitHub Secrets 是否正确配置
2. 生成新的 Token 并重新配置
3. 确保 Token 有正确的作用域

### Q2: "PyPI 上已存在该版本"

**原因**：该版本号已经发布过

**解决**：
- 使用新的版本号（遵循语义版本化）
- 或使用 `.postN` 后缀发布后续修复

### Q3: 包安装时提示 "找不到依赖"

**原因**：可能是依赖版本约束过严

**解决**：
1. 检查 `pyproject.toml` 中的依赖版本
2. 对于 Python 3.8 支持，确保 numpy >= 1.17.0, scipy >= 1.5.0

### Q4: 工作流中的某个步骤失败

**解决步骤**：
1. 查看 GitHub Actions 日志
2. 根据错误消息判断原因
3. 在本地复现问题
4. 修复问题后重新提交
5. 重新手动触发工作流

### Q5: 想要撤回已发布的版本

**注意**：PyPI 上发布的包无法删除，但可以：
- 发布新版本修复问题
- 在 PyPI 上将旧版本标记为 "yanked"（已弃用）
- 详见 [PEP 592](https://peps.python.org/pep-0592/)

## 🛡️ 安全建议

1. **定期轮换 Token**
   - 每 6 个月重新生成一次 Token
   - Token 泄露立即重新生成

2. **限制 Token 作用域**
   - 仅为 `deep-solutions` 项目分配 Token
   - 避免使用 "Entire account" 作用域

3. **监控发布活动**
   - 定期检查 GitHub Actions 日志
   - 确保只有授权人员进行发布

4. **备份和恢复**
   - 保存 Token 的安全备份
   - 定期测试 Token 的有效性
